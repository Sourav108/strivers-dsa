# 3Sum (Step 3.3 — Hard Array Problems)

This is a complete, interview-ready note in C++ following the standard 9-section format.

- **Source**: [LeetCode #15 - 3Sum](https://leetcode.com/problems/3sum/) | [TakeUForward](https://takeuforward.org/data-structure/3-sum-find-triplets-that-add-up-to-a-zero/)
- **Difficulty**: Medium
- **Statement**: Given an integer array `nums`, find all unique triplets `[nums[i], nums[j], nums[k]]` such that $i \neq j \neq k$ and $nums[i] + nums[j] + nums[k] == 0$. The solution set must not contain duplicate triplets.

---

## 1. Problem, Restated

Find all unique groups of three numbers in an array that add up to zero. Constraints that matter: $n$ can be up to $3000$, elements can be negative or positive, and the output must not contain duplicate triplets even if duplicate values appear in `nums`.

---

## 2. Intuition & Pattern

Sorting + Two Pointers. If the array is unsorted, finding three numbers takes $\mathcal{O}(n^3)$ or requires hash sets. But if we sort the array first in $\mathcal{O}(n \log n)$, we can fix the first number $nums[i]$ and use two pointers (`left` and `right`) to search for the remaining two numbers in $\mathcal{O}(n)$ time. Duplicate triplets are eliminated in $\mathcal{O}(1)$ auxiliary space simply by skipping over consecutive identical values after each match.

---

## 3. Approach 1 — Brute Force

### Idea
Three Nested Loops with Set Deduplication: Use three nested loops $(i, j, k)$ to evaluate all possible triplets. If the sum is 0, sort the triplet and insert into an `std::set<vector<int>>` to eliminate duplicates.

### C++17 Code
```cpp
#include <vector>
#include <set>
#include <algorithm>
using namespace std;

vector<vector<int>> threeSumBrute(vector<int>& nums) {
    set<vector<int>> uniqueTriplets;
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            for (int k = j + 1; k < n; k++) {
                if (nums[i] + nums[j] + nums[k] == 0) {
                    vector<int> triplet = {nums[i], nums[j], nums[k]};
                    sort(triplet.begin(), triplet.end());
                    uniqueTriplets.insert(triplet);
                }
            }
        }
    }
    return vector<vector<int>>(uniqueTriplets.begin(), uniqueTriplets.end());
}
```

### Complexity Derivation
- **Time Complexity**: $\mathcal{O}(n^3 \log(\text{unique triplets}))$ — 3 nested loops plus logarithmic insertion into a Red-Black tree set.
- **Space Complexity**: $\mathcal{O}(2 \times \text{triplets})$ — set storage and resulting output vector.
- **Why it's not good enough**: Generates $\mathcal{O}(n^3)$ combinations which causes Time Limit Exceeded (TLE) at $n = 3000$ ($n^3 = 2.7 \times 10^{10}$ operations).

---

## 4. Approach 2 — Better

### Idea
Two Loops + Hash Set Lookup: Loop $i$ and $j$. For each pair, the required third value is $-(nums[i] + nums[j])$. Look for this complement in an `unordered_set` of elements seen in the current iteration.

### C++17 Code
```cpp
#include <vector>
#include <unordered_set>
#include <set>
#include <algorithm>
using namespace std;

vector<vector<int>> threeSumBetter(vector<int>& nums) {
    set<vector<int>> uniqueTriplets;
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        unordered_set<int> seen;
        for (int j = i + 1; j < n; j++) {
            int third = -(nums[i] + nums[j]);
            if (seen.count(third)) {
                vector<int> triplet = {nums[i], nums[j], third};
                sort(triplet.begin(), triplet.end());
                uniqueTriplets.insert(triplet);
            }
            seen.insert(nums[j]);
        }
    }
    return vector<vector<int>>(uniqueTriplets.begin(), uniqueTriplets.end());
}
```

### Complexity Derivation
- **Time Complexity**: $\mathcal{O}(n^2 \log(\text{triplets}))$ — two nested loops with hash map queries and set deduplication.
- **Space Complexity**: $\mathcal{O}(n + \text{triplets})$ — hash set allocations per outer iteration and tree set storage.
- **Why it's still not optimal**: Requires dynamic memory allocations for hash sets on every outer loop iteration and extra storage for the deduplication set.

## 5. Approach 3 — Optimal

### Idea
Sort + Two Pointers (In-Place Deduplication): Sort the array in $\mathcal{O}(n \log n)$. For each index $i$, if $i > 0$ and $nums[i] == nums[i-1]$, skip to prevent duplicate triplets. Initialize `left = i + 1` and `right = n - 1`. Check `sum = nums[i] + nums[left] + nums[right]`: if `sum == 0`, record the triplet, advance `left` past duplicates, and decrement `right` past duplicates. If `sum < 0`, advance `left++`; else decrement `right--`.

### C++17 Code
```cpp
#include <vector>
#include <algorithm>
using namespace std;

vector<vector<int>> threeSum(vector<int>& nums) {
    vector<vector<int>> res;
    int n = nums.size();
    if (n < 3) return res;
    
    sort(nums.begin(), nums.end());
    
    for (int i = 0; i < n - 2; i++) {
        // Skip duplicate values for the first element
        if (i > 0 && nums[i] == nums[i - 1]) continue;
        
        // Early pruning: smallest possible sum > 0
        if (nums[i] + nums[i + 1] + nums[i + 2] > 0) break;
        // Early pruning: largest possible sum < 0
        if (nums[i] + nums[n - 2] + nums[n - 1] < 0) continue;
        
        int left = i + 1, right = n - 1;
        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];
            if (sum == 0) {
                res.push_back({nums[i], nums[left], nums[right]});
                left++;
                right--;
                // Skip duplicates for the second and third elements
                while (left < right && nums[left] == nums[left - 1]) left++;
                while (left < right && nums[right] == nums[right + 1]) right--;
            } else if (sum < 0) {
                left++;
            } else {
                right--;
            }
        }
    }
    return res;
}
```

### Complexity Derivation
- **Time Complexity**: $\mathcal{O}(n^2)$ — sorting takes $\mathcal{O}(n \log n)$, and the outer loop runs $n$ times with an inner two-pointer pass of at most $n$ steps.
- **Space Complexity**: $\mathcal{O}(1)$ auxiliary space (excluding output storage) — sorting is done in-place.
- **Why this is optimal**: According to the **3SUM Conjecture** in computational complexity, no sub-quadratic algorithm ($\mathcal{O}(n^{2-\epsilon})$ for $\epsilon > 0$) exists for 3SUM. $\mathcal{O}(n^2)$ matches the best known theoretical complexity.

## 6. Dry Run

`nums = [-1, 0, 1, 2, -1, -4]` -> sorted: `[-4, -1, -1, 0, 1, 2]`

| Step | Action / Comparisons | State Change / Found Triplet | Result State |
|---|---|---|---|
| `i=0 (x=-4)` | left=1 (-1), right=5 (2) -> sum = -3 < 0 | `left++` -> left=2 (-1) | sum=-3 |
| `i=0 (cont)` | left=2 (-1), right=5 (2) -> sum = -3 < 0 | `left++` -> left=3 (0) | sum=-3 |
| `i=0 (cont)` | left=3 (0), right=5 (2) -> sum = -2 < 0 | `left++` -> left=4 (1) | sum=-2 |
| `i=0 (cont)` | left=4 (1), right=5 (2) -> sum = -1 < 0 | `left++` -> left=5 -> loop ends | no triplet |
| `i=1 (x=-1)` | left=2 (-1), right=5 (2) -> sum = 0 | **Found [-1, -1, 2]** -> left=3, right=4 | `res=[[-1,-1,2]]` |
| `i=1 (cont)` | left=3 (0), right=4 (1) -> sum = 0 | **Found [-1, 0, 1]** -> left=4, right=3 | `res=[[-1,-1,2],[-1,0,1]]` |
| `i=2 (x=-1)` | `nums[2] == nums[1]` | Duplicate value -> skip iteration | res unchanged |
| `i=3 (x=0)` | left=4 (1), right=5 (2) -> sum = 3 > 0 | `right--` -> right=4 -> loop ends | `res` unchanged |
| `Final` | - | Final Output: `[[-1, -1, 2], [-1, 0, 1]]` | ✅ Correct |

## 7. Edge Cases & Common Bugs

### Edge Cases
- **Array with fewer than 3 elements** (`[1, 2]` -> returns `[]`).
- **Array with all zeroes** (`[0, 0, 0, 0]` -> duplicate skipping ensures exactly one triplet `[0, 0, 0]` is returned).
- **No valid triplet exists** (`[1, 2, 3]` -> returns `[]`).
- **Potential integer overflow**: If numbers can be close to `INT_MAX` or `INT_MIN`, computing `nums[i] + nums[left] + nums[right]` can overflow 32-bit `int`; in such constraints, cast sum to `(long long)`.

### Common Bugs to Avoid
- Forgetting `while (left < right && nums[left] == nums[left - 1]) left++` after finding a triplet, causing duplicate triplets in the output.
- Advancing `left` without checking `left < right` inside the duplicate-skipping while loop, causing out-of-bounds pointer index.

## 8. Follow-Up Questions (Interview Style)

- **Q1: Why is sorting the array acceptable when aiming for O(n^2) total time?**  
  **A**: Sorting takes $\mathcal{O}(n \log n)$, while the nested two-pointer scan takes $\mathcal{O}(n^2)$. Since $\mathcal{O}(n \log n)$ is asymptotically smaller than $\mathcal{O}(n^2)$, sorting adds zero overhead to the overall complexity.

- **Q2: How do we strictly prevent duplicate triplets without using `std::set`?**  
  **A**: 1) Skip duplicate outer elements: `if (i > 0 && nums[i] == nums[i-1]) continue;`. 2) After finding a triplet, advance pointers past duplicate values: `while (left < right && nums[left] == nums[left-1]) left++; while (left < right && nums[right] == nums[right+1]) right--;`.

- **Q3: How to solve 3Sum Closest (finding triplet whose sum is closest to target)?**  
  **A**: Sort array, run Two Pointers, compute `diff = abs(target - sum)`. If `diff < minDiff`, update `closestSum = sum`. If `sum < target` `left++`, else `right--` in $\mathcal{O}(n^2)$ time and $\mathcal{O}(1)$ space.

- **Q4: What is the 3SUM Conjecture in computational complexity?**  
  **A**: The 3SUM Conjecture states that no algorithm can solve the 3SUM problem in $\mathcal{O}(n^{2-\epsilon})$ time for any $\epsilon > 0$. It forms the foundation for lower bounds in computational geometry.

- **Q5: What if the array is huge and stored across distributed nodes?**  
  **A**: Partition data into hash ranges, replicate boundary candidate buckets across nodes, and run parallel two-pointer merges.

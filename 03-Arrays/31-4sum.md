## 1. Problem, Restated

Find all unique quadruplets $[a, b, c, d]$ summing to `target`.

- **Input**: Vector of integers `nums`.
- **Output**: Result as specified by problem requirements.
- **Key Constraints**: $n$ up to $10^5$, elements can be negative/positive, time limit 1.0s.

---

## 2. Intuition & Pattern

Sort + Double Loop + Two Pointers with 64-bit integer overflow protection.

- **Underlying Pattern**: Array Manipulation / Mathematical Invariants / Pointers.
- **The "Aha!" Moment**: Recognizing how to avoid redundant work by storing running state or leveraging sorting invariants.

## 3. Approach 1 — Brute Force

### Idea

```cpp
#include <climits>
#include <set>
#include <unordered_map>
using namespace std;

vector<vector<int>> fourSumBrute(vector<int>& nums, int target) {
    // 4 nested loops + set
    return {};
}
```

### Complexity Derivation
- **Time Complexity**: O(n^4)
- **Space Complexity**: O(quads)
- **Why it's not good enough**: 4 nested loops take $\mathcal{O}(n^4)$ time, triggering TLE at $n = 200$.

---

## 4. Approach 2 — Better

### Idea
Three Loops + Hash Set: Loop $i, j, k$, look for $target - (nums[i] + nums[j] + nums[k])$ in a hash set of inner elements, and deduplicate with `std::set<vector<int>>`.

### C++17 Code
```cpp
#include <vector>
#include <unordered_set>
#include <set>
#include <algorithm>
using namespace std;

vector<vector<int>> fourSumBetter(vector<int>& nums, int target) {
    set<vector<int>> uniqueQuads;
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            unordered_set<long long> seen;
            for (int k = j + 1; k < n; k++) {
                long long needed = (long long)target - (nums[i] + nums[j] + nums[k]);
                if (seen.count(needed)) {
                    vector<int> quad = {nums[i], nums[j], nums[k], (int)needed};
                    sort(quad.begin(), quad.end());
                    uniqueQuads.insert(quad);
                }
                seen.insert(nums[k]);
            }
        }
    }
    return vector<vector<int>>(uniqueQuads.begin(), uniqueQuads.end());
}
```

### Complexity Derivation
- **Time Complexity**: $\mathcal{O}(n^3 \log(\text{quads}))$.
- **Space Complexity**: $\mathcal{O}(n + \text{quads})$ extra space.
- **Why it's still not optimal**: Heavy memory usage from sets; sort + two-pointers solves it in $\mathcal{O}(n^3)$ without extra set space.

---

## 5. Approach 3 — Optimal

### Idea
Sort + Nested Loops + Two Pointers: Sort array. Loop $i$ and $j$, skipping duplicate values. Use two pointers `left = j + 1, right = n - 1` with 64-bit sum check `(long long)nums[i] + nums[j] + nums[left] + nums[right] == target`.

### C++17 Code
```cpp
#include <vector>
#include <algorithm>
#include <climits>
#include <unordered_map>
#include <unordered_set>
using namespace std;

vector<vector<int>> fourSumOptimal(vector<int>& nums, int target) {
    vector<vector<int>> res;
    sort(nums.begin(), nums.end());
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;
        for (int j = i + 1; j < n; j++) {
            if (j > i + 1 && nums[j] == nums[j - 1]) continue;
            int left = j + 1, right = n - 1;
            while (left < right) {
                long long sum = (long long)nums[i] + nums[j] + nums[left] + nums[right];
                if (sum == target) {
                    res.push_back({nums[i], nums[j], nums[left], nums[right]});
                    left++; right--;
                    while (left < right && nums[left] == nums[left - 1]) left++;
                    while (left < right && nums[right] == nums[right + 1]) right--;
                } else if (sum < target) left++;
                else right--;
            }
        }
    }
    return res;
}
```

### Complexity Derivation
- **Time Complexity**: O(n^3)
- **Space Complexity**: O(1)
- **Why this is optimal**: Reduces degree of freedom via sorting to $\mathcal{O}(n^3)$ time and $\mathcal{O}(1)$ auxiliary space.

## 6. Dry Run

| Step | Action / State Change | Result |

## 7. Edge Cases & Common Bugs

### Edge Cases
- Array with 4 huge positive integers ($10^9 + 10^9 + 10^9 + 10^9$) -> handled by `(long long)` casting.
- Fewer than 4 elements -> returns `[]`.

### Common Bugs to Avoid
- Omitting `(long long)` casting, causing signed 32-bit integer overflow.
- Forgetting duplicate skips on `j` (`if (j > i + 1 && nums[j] == nums[j - 1]) continue`).

## 8. Follow-Up Questions (Interview Style)

- **Q1: Why is 64-bit `long long` casting necessary in 4Sum?**  
  **A**: Four elements at extreme constraints (e.g. $10^9 + 10^9 + 10^9 + 10^9 = 4 \times 10^9$) exceed `INT_MAX` ($2.14 \times 10^9$). Computing sum as `(long long)nums[i] + nums[j] + nums[left] + nums[right]` prevents undefined integer overflow behavior.

- **Q2: How does 4Sum generalize to K-Sum?**  
  **A**: Use recursive reduction: for $K > 2$, sort array, loop through $i$, fix $nums[i]$, and recursively solve $(K-1)$-Sum for `target - nums[i]`. When $K = 2$, execute the standard Two-Pointer search in $\mathcal{O}(n)$ time. Total time $\mathcal{O}(n^{K-1})$.

- **Q3: What early pruning / bounding optimizations can speed up 4Sum by 10x?**  
  **A**: 1) If `(long long)nums[i] + nums[i+1] + nums[i+2] + nums[i+3] > target`, break immediately (smallest sum exceeds target). 2) If `(long long)nums[i] + nums[n-3] + nums[n-2] + nums[n-1] < target`, continue (largest sum cannot reach target).

- **Q4: How does 4Sum II (LeetCode 454) differ when 4 separate arrays are given?**  
  **A**: When 4 independent arrays are given, elements can be paired independently: compute pairwise sums of $A$ and $B$ in a hash map $\mathcal{O}(n^2)$, then query complements in $C$ and $D$ in $\mathcal{O}(n^2)$ time and $\mathcal{O}(n^2)$ space.

- **Q5: What is the theoretical space-time tradeoff for 4Sum?**  
  **A**: Using a hash map of pair sums solves 4Sum in $\mathcal{O}(n^2)$ time but requires $\mathcal{O}(n^2)$ auxiliary space and complex duplicate index handling.
